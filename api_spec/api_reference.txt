--------------------------------------------------------------------------------
GENERAL INFORMATION
--------------------------------------------------------------------------------

Base URL (local / Docker):   http://localhost:8080
API base path:               /api
Health check (no /api):      GET http://localhost:8080/health

Content type:
  - All JSON endpoints accept and return  application/json
  - Certificate upload uses               multipart/form-data
  - Certificate download returns          application/pdf (binary stream)

Authentication:
  - All endpoints EXCEPT /api/auth/* require a JWT.
  - Pass it in the header:   Authorization: Bearer <JWT>
  - Obtain tokens from /auth/register, /auth/login, or /auth/refresh.
    These return "accessToken" (short-lived JWT), "refreshToken" (opaque,
    revocable), and "expiresIn" (seconds). "token" is still returned as a
    deprecated alias of accessToken.
  - Default access-token lifetime (ACCESS_TOKEN_TTL): 15m. Use /auth/refresh to
    obtain a new pair; the old refresh token is rotated (revoked).
  - New accounts receive an email verification token on registration
    (soft verification: the account is usable immediately; "emailVerified"
    becomes true after POST /auth/verify-email).

Email delivery:
  - MAIL_PROVIDER=log (default) writes reset/verification tokens to the server
    log: "[mailer] email verification for <email>: token=<tok>".
  - MAIL_PROVIDER=smtp sends real email (SMTP_HOST/PORT/USERNAME/PASSWORD,
    MAIL_FROM). Gmail: smtp.gmail.com:587 with a 16-char App Password.

Local testing bypass:
  - Set SKIP_JWT_VALIDATION=true (development only; refused in production) to
    bypass JWT auth. Requests then run as a synthetic super_admin.
  - Override the injected identity per request with headers:
      X-Debug-User-Id, X-Debug-Role, X-Debug-Church-Id
  - Seed the fixed debug user first (make seed / make docker-seed) so that
    foreign-key-bound operations succeed.

Roles (lowest to highest privilege):
  user, priest, associate_priest, church_admin, super_admin
  - super_admin   : may perform any action.
  - church_admin  : scoped to their own church (enforced in routing + service);
                    full administrative control of that church's resources.
  - priest /      : church staff scoped to their own church. May manage
    associate_      pastoral content (announcements, events) for that church.
    priest          No administrative powers (halls, booking status, cemetery
                    plots/requests, user roles stay church_admin/super_admin).
  - user          : manages only their own bookings, service requests,
                    event registrations, profile, and certificates.

--------------------------------------------------------------------------------
STANDARD RESPONSE SHAPES
--------------------------------------------------------------------------------

Error envelope (any 4xx / 5xx):
  {
    "message": "human readable message",
    "code": "machine_readable_code",        // e.g. bad_request, unauthorized,
    "details": { ... }                       // forbidden, not_found, conflict,
  }                                           // internal (details is optional)

Common error codes & HTTP status:
  400 bad_request              - invalid JSON / validation failure
  401 unauthorized             - missing/invalid token or bad credentials
  403 forbidden                - insufficient permissions
  404 not_found                - resource does not exist
  409 conflict                 - duplicate / state conflict
  413 payload_too_large        - uploaded file exceeds limit
  415 unsupported_media_type   - non-PDF certificate upload
  500 internal                 - unexpected server error

Paginated list envelope (all list endpoints):
  {
    "data": [ ... ],
    "pagination": {
      "page": 1,
      "limit": 20,
      "total": 134,
      "totalPages": 7
    }
  }

Common pagination query parameters (all list endpoints):
  page   integer  default 1    (minimum 1)
  limit  integer  default 20   (range 1..100; values above 100 are clamped)
  search string   optional     case-insensitive text filter over the most
                               relevant text fields of the listed resource
                               (see each list endpoint for the fields matched)

Date/time formats:
  - Timestamps in JSON bodies are RFC3339 (e.g. "2025-06-01T14:00:00Z").
  - Certificate "issueDate" form field is YYYY-MM-DD.

--------------------------------------------------------------------------------
1.1  Register a new user
--------------------------------------------------------------------------------
Method : POST
URL    : /api/auth/register
Auth   : None (public)
Headers:
  Content-Type: application/json

Request body:
  {
    "name":     "Jane Doe",         // required, non-empty
    "email":    "jane@example.com", // required, valid email, unique
    "password": "supersecret",      // required, minimum 8 characters
    "phone":    "+1-555-0100",      // optional, nullable
    "unit":     "Youth Ministry",   // optional, nullable
    "churchId": "uuid-or-null"      // optional, nullable
  }

Description:
  Creates a user with the default role "user" and returns a token pair plus the
  created user object. Password is bcrypt-hashed and never returned.

Success: 201 Created
  {
    "accessToken": "<jwt>",
    "refreshToken": "<opaque-token>",
    "expiresIn": 900,
    "token": "<jwt>",               // deprecated alias of accessToken
    "user": {
      "id": "uuid",
      "name": "Jane Doe",
      "email": "jane@example.com",
      "phone": "+1-555-0100",
      "unit": "Youth Ministry",
      "profilePic": null,
      "role": "user",
      "churchId": null,
      "emailVerified": false,
      "createdAt": "2025-01-01T00:00:00Z"
    }
  }

Errors:
  400 bad_request  - missing name, invalid email, or password < 8 chars
  409 conflict     - email already registered

--------------------------------------------------------------------------------
1.2  Log in
--------------------------------------------------------------------------------
Method : POST
URL    : /api/auth/login
Auth   : None (public)
Headers:
  Content-Type: application/json

Request body:
  {
    "email":    "jane@example.com",  // required
    "password": "supersecret"        // required
  }

Description:
  Verifies credentials and returns a token pair plus the user object (same
  shape as register).

Success: 200 OK
  { "accessToken": "<jwt>", "refreshToken": "<opaque>", "expiresIn": 900,
    "token": "<jwt>", "user": { ... } }

Errors:
  400 bad_request   - email or password missing/invalid format
  401 unauthorized  - invalid email or password

--------------------------------------------------------------------------------
1.3  Refresh tokens
--------------------------------------------------------------------------------
Method : POST
URL    : /api/auth/refresh
Auth   : None (public)
Headers:
  Content-Type: application/json

Request body:
  { "refreshToken": "<opaque-token>" }    // required

Description:
  Rotates the refresh token: the presented token is revoked and a new
  access + refresh pair is issued. Reuse of a revoked/expired token fails.

Success: 200 OK  -> same shape as login (accessToken, refreshToken, expiresIn,
                    token, user)

Errors:
  400 bad_request   - refreshToken missing
  401 unauthorized  - invalid or expired refresh token

--------------------------------------------------------------------------------
1.4  Logout (single session)

URL    : /api/auth/logout
Auth   : None (public)
Headers:
  Content-Type: application/json

Request body:
  { "refreshToken": "<opaque-token>" }    // required

Description:
  Revokes the presented refresh token. Idempotent.

Success: 204 No Content

Errors:
  400 bad_request   - refreshToken missing

--------------------------------------------------------------------------------
1.5  Forgot password
--------------------------------------------------------------------------------
Method : POST
URL    : /api/auth/forgot-password
Auth   : None (public)
Headers:
  Content-Type: application/json

Request body:
  { "email": "jane@example.com" }    // required

Description:
  Always returns 200 (no account enumeration). If the email is registered a
  single-use reset token is delivered via the Mailer. In development the token

Success: 200 OK  -> { "message": "if the email is registered, a reset link has been sent" }

--------------------------------------------------------------------------------
1.6  Reset password
--------------------------------------------------------------------------------
Method : POST
URL    : /api/auth/reset-password
Auth   : None (public)
Headers:

Request body:

Description:

Success: 200 OK  -> { "message": "password updated" }

Errors:
  400 bad_request   - token missing/invalid/expired, or password < 8 chars

--------------------------------------------------------------------------------

  {

9. CERTIFICATES
================================================================================
All routes require:  Authorization: Bearer <JWT>

Certificate type (enum):
  baptism, confirmation, marriage, first_communion, death, other

Access rule for all certificate routes:
  The certificate must belong to a user who is the requester themselves, OR
  a user the requester administers (managing admin).

--------------------------------------------------------------------------------
9.1  List a user's certificates
--------------------------------------------------------------------------------
Method : GET
URL    : /api/users/{userId}/certificates
Access : the user themselves or a managing admin
Path params: userId string
Query parameters:
  type   string  filter by certificate type
  page, limit    (pagination)

Success: 200 OK -> paginated envelope of certificate metadata objects:
  {
    "id":"uuid", "userId":"uuid", "uploadedByUserId":"uuid",
    "type":"baptism", "certificateNumber":"BAP-001", "fullName":"...",
    "issueDate":"..." | null, "fileName":"baptism.pdf",
    "mimeType":"application/pdf", "fileSize": 12345, "notes": null,
    "createdAt":"..."
  }
  (The on-disk file path is internal and never returned.)

--------------------------------------------------------------------------------
9.2  Upload a certificate
--------------------------------------------------------------------------------
Method : POST
URL    : /api/users/{userId}/certificates
Access : the user themselves or a managing admin
Headers:
  Content-Type: multipart/form-data
Path params: userId string

Form fields (multipart/form-data):
  file               (required) the PDF file part; must be application/pdf
  type               (required) certificate type enum
  certificateNumber  (required) unique certificate number
  fullName           (required) name on the certificate
  issueDate          (optional) YYYY-MM-DD
  notes              (optional) free text

Limits:
  - Only PDF files are accepted.
  - Max file size is governed by MAX_UPLOAD_BYTES (default 10 MiB / 10485760).

Description:
  Validates file type and size, stores the PDF on disk under STORAGE_DIR, and
  records metadata in the database.

Success: 201 Created -> certificate metadata object (see 9.1)

Errors :
  400 bad_request             - missing file / invalid form / bad issueDate
  403 forbidden
  404 not_found (user)
  409 conflict                - certificate number already exists
  413 payload_too_large       - file exceeds the configured limit
  415 unsupported_media_type  - file is not a PDF

Example (curl):
  curl -X POST "http://localhost:8080/api/users/$USER_ID/certificates" \
    -H "Authorization: Bearer $TOKEN" \
    -F 'file=@baptism.pdf;type=application/pdf' \
    -F 'type=baptism' \
    -F 'certificateNumber=BAP-001' \
    -F 'fullName=Jane Doe' \
    -F 'issueDate=2000-05-01'

--------------------------------------------------------------------------------
9.3  Download a certificate
--------------------------------------------------------------------------------
Method : GET
URL    : /api/certificates/{certificateId}/download
Access : the owning user or a managing admin
Path params: certificateId string

Description:
  Streams the stored PDF back to the client.

Success: 200 OK
  Response headers:
    Content-Type: application/pdf
    Content-Length: <file size>
    Content-Disposition: attachment; filename="<original file name>"
  Body: binary PDF content.

Errors : 403 forbidden, 404 not_found

11. COMMUNITIES
================================================================================
All routes require:  Authorization: Bearer <JWT>

Community visibility:
  All authenticated users may discover communities and request membership.
  The creator is the community admin. Only active members may read or post
  messages. Only the community admin may review requests, remove members, or
  moderate messages. Members may delete their own messages and leave.

11.1 List communities
Method: GET  URL: /api/communities
Success: 200 OK -> { "data": [ community objects ] }
Each object includes id, creatorId, name, description, and createdAt. The
requester's status ("active", "pending", or "declined") and isAdmin are
included when true/non-empty; nonmembers have neither field.

11.2 Create a community
Method: POST  URL: /api/communities
Body: { "name": "Choir", "description": "Optional description" }
Success: 201 Created -> community object; the creator is made an active admin.
Errors: 400 bad_request

11.3 Request membership
Method: POST  URL: /api/communities/{communityId}/requests
Success: 201 Created -> pending membership request
Errors: 404 not_found, 409 conflict (already active or pending)

11.4 Review membership requests (admin only)
  GET  /api/communities/{communityId}/requests
       -> 200 OK { "data": [ pending membership objects ] }
  POST /api/communities/{communityId}/requests/{requestId}/approve
       -> 204 No Content
  POST /api/communities/{communityId}/requests/{requestId}/decline
       -> 204 No Content
Errors: 403 forbidden, 404 not_found

11.5 List and remove members
  GET /api/communities/{communityId}/members
       -> 200 OK { "data": [ active membership objects ] } (active members only)
  DELETE /api/communities/{communityId}/members/{userId}
       -> 204 No Content (admin only; admins cannot remove themselves)
  DELETE /api/communities/{communityId}/leave
       -> 204 No Content (an admin leaving transfers admin to another active
          member; the only admin cannot leave until another member is active)
Errors: 403 forbidden, 404 not_found

11.6 Community messages
  GET    /api/communities/{communityId}/messages?latest=1&limit=50
  GET    /api/communities/{communityId}/messages?before={seq}&limit=50
  GET    /api/communities/{communityId}/messages?after={seq}&limit=50
       -> 200 OK { "data": [ oldest-first messages ], "hasMore": boolean }
  POST   /api/communities/{communityId}/messages
       Body: { "content": "Hello!" }
       -> 201 Created -> message object
  DELETE /api/communities/{communityId}/messages/{messageId}
       -> 204 No Content (message author or community admin)
Errors: 400 bad_request, 403 not_member/forbidden, 404 not_found
